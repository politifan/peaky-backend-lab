Распакуйте целиком в новую учебную папку. Python 3.12. Windows: py -3.12 -m venv .venv, затем .venv/Scripts/python.exe -m pip install -r requirements.txt. Linux/macOS: python3.12 и .venv/bin/python. Ниже python означает выбранный путь своей venv. Активация/изменение ExecutionPolicy не нужны. Исторические DOCX справочные, текущая методика — Stepik и этот файл, TXT/Markdown достаточен.

Рабочая папка student/lab, отдельная от basic. Остановите свой прежний API на 8000. docker compose up --build -d, затем docker compose logs migrate seed api. Проект peaky-backend-advanced-lantern: PostgreSQL loopback:55432, API:8000, receiver:8001. Тома и старые записи сохраняются.

Обычный faults.py исправен. После успешного первого цикла назначьте ОДИН случай: python inject.py migration/worker/cache/duplicate. Для Compose: docker compose exec -T api python inject.py worker. Перезапустите свой API и наблюдайте только этот дефект. inject.py none возвращает обычные адаптеры и имя stock.available после учебного переименования, сохраняя строки. tests/test_incident_contracts.py проверяет старый fencing token, разделение cache и один эффект event. PEAKY_TEST_FAULT=worker/cache/duplicate включает открытый контрпример только для соответствующего теста; после возврата обычного режима результат зелёный.
Бронь: новый key/qty → 201; точный повтор → 200, тот же id, replayed=true; изменённый qty → 409. tests/test_pg_invariants.py требует настоящую PostgreSQL. Подготовьте выделенный учебный стенд; тест проверяет конкурентный остаток, SQLite не заменяет его.

Авторизация интегрирована: AUTH_MODE=demo по умолчанию принимает открытые labels. AUTH_MODE=jwt проверяет подписанный JWT в Depends(identity) настоящих маршрутов. Для PowerShell своей копии:
$env:AUTH_MODE='jwt'
$env:JWT_SECRET='my-isolated-training-jwt-secret-32chars'
docker compose up -d --build api
docker compose exec -T api python issue_demo_token.py --user alice --tenant school-a --scopes 'read write'
В Bash используйте export. Issuer — локальный доверенный учебный инструмент, не сервер входа. Запросы без/с истёкшим токеном/неверным audience → 401; read-only запись → 403; чужой tenant/владелец → 404.
docker compose exec -T api python -m pytest tests/test_jwt_routes.py -q
Для общего smoke/старых demo-команд верните AUTH_MODE=demo с пересозданием своего api.

Подписанная доставка:
docker compose exec -T -e DELIVERY_URL=http://receiver:8001/mock/events api python outbox_worker.py
HMAC(timestamp + newline + exact body), окно 300 секунд. Receiver сохраняет (tenant,event), hash намерения и payload одной SQLite-транзакцией в receiver-data. Первый приём → 201, точный повтор → 200/replayed без второго эффекта, другое тело прежнего ключа → 409, неверная/просроченная подпись → 401. Открытый DELIVERY_SECRET по умолчанию только учебный; свой задают одинаково api/receiver и пересоздают контейнеры с теми же томами.
docker compose exec -T api python -m pytest tests/test_receiver.py -q
Тест подтверждает повтор в новом интерпретаторе, а не только памяти. Самостоятельный опыт: сохранить outbox id/event, получить приём с потерянным для sender подтверждением, перезапустить receiver с тем же томом, повторить и сверить одну запись deliveries и outbox.sent. Новый event не считается точным повтором.
