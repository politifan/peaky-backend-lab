Основной app/main.py теперь исправен: commit сохраняет заявку. Сначала:
python check_practice.py app/main.py --mode service
Затем только в назначенном уроке своей копии:
python configure_persistence.py lost_commit
python check_practice.py app/main.py --mode persistence
Ожидается красная сохранность. Исследуйте новую сессию и старый committed id. Восстановите транзакцию или верните готовый профиль python configure_persistence.py none. После изменения перезапустите API с той же БД. Профиль меняет один marker, данные не удаляются. Check_practice без --database-url использует временную SQLite; PostgreSQL/миграции проверяют отдельно.
Compose peaky-backend-basic, PostgreSQL loopback:5432. DATABASE_URL и JWT_SECRET задаются в PowerShell через $env:, в Bash через export, .env.example автоматически не читается. Миграции до uvicorn app.main:app; секрет своей копии не короче 32 символов. /users регистрирует, /token принимает form, POST /tickets требует Idempotency-Key. Новый смысл — новый ключ; изменённое тело прежнего ключа — конфликт. Один сервис заявок — итог, прежние строки сохраняются после нового процесса.
